基础请求

适合先确认规则开关、URL 匹配、method 条件、响应替换和命中计数。

同源静态资源

Fetch · GET JSON

读取固定 JSON 文件。可测试包含、正则、精确 URL 匹配及 JSON 响应替换。

GET /playground/fixtures/profile.json?case=fetch-get

Fetch · POST JSON

带 JSON body 的 POST。可测试 method 匹配、静态重定向、mock / replace。

POST /playground/fixtures/echo.json?case=fetch-post

Fetch · Request 对象

从 GET Request 实例发出 POST，由 init 覆盖 method 并添加 body。

GET /playground/fixtures/profile.json?case=request-override

Fetch · 并发请求

同时发出 5 个带不同 query 的请求，观察命中累计、并发处理和请求 URL。

GET profile.json?case=burst-1…5

XHR · JSON responseType

使用 responseType=json 读取资源。适合测试 XHR 命中、响应替换和回调事件。

GET /playground/fixtures/profile.json?case=xhr-json

XHR · text responseType

读取纯文本 fixture，观察 responseText 与 readyState / loadend 结果。

GET /playground/fixtures/message.txt?case=xhr-text

XHR · POST JSON

发送 JSON 请求体。静态 Pages 没有 POST API，未命中时会显示站点的原始响应。

POST /playground/fixtures/echo.json?case=xhr-post

XHR · ArrayBuffer

用二进制响应类型读取 JSON 字节。适合确认不支持的响应替换是否安全回退。

GET profile.json?case=xhr-arraybuffer

使用说明与支持边界

快速配置一条规则

  1. 打开 Ajax Proxy 面板，创建一条响应规则。
  2. 复制下方 URL 的路径片段作为匹配 URL，例如 playground/fixtures/profile.json。
  3. 先选普通包含匹配，并启用规则；请求按钮可立即重复点击。
  4. 配置 JSON body / status 替换后，观察页面响应和命中计数。
普通匹配 URL 不要求以斜杠开头。规则需启用，且全局 V3 开关已打开。
  • fixtures/profile.jsonGET JSON；基本 Fetch / XHR 和静态响应替换。
  • fixtures/message.txtGET text；XHR text responseType。
  • fixtures/redirect-target.json重定向目标；可配置从 profile.json 跳转至此。
  • fixtures/echo.jsonPOST 目标；Pages 无后端，适合测试拦截响应或重定向。

边界与回退

这些场景用来确认插件只在预期范围工作。

404 原始响应

请求不存在的静态文件。未命中时会显示 Pages 返回的 404；命中时可验证规则响应。

GET /playground/fixtures/not-found.json

Dedicated Worker · Fetch

当前插件不拦截 Dedicated Worker 内的请求。此按钮只验证 Worker 原生 Fetch 可用，作为支持范围对照。

worker.js → fixtures/profile.json

跨源 CORS · Fetch

可选地请求公开 JSON 示例站点。它依赖网络与对方 CORS 策略，不作为离线基线。

https://jsonplaceholder.typicode.com/todos/1

method 不匹配

对已有 GET fixture 发 DELETE。GET 规则不应因 URL 相同而匹配。

DELETE /playground/fixtures/profile.json

常用测试 URL

使用包含匹配时复制路径片段；精确匹配时复制页面显示的完整 URL。

  • 加载中…GET JSON 基线。
  • 加载中…POST 请求体和响应行为。
  • 加载中…srcdoc 子 frame 请求。

此页面是纯静态测试夹具，不上传请求记录，也不会自动发送网络请求。只有点击“跨源 GET”时才会向 JSONPlaceholder 发起公开测试请求。GitHub Pages 没有服务端 POST API；POST 的原始响应可能是 404 / 405。
