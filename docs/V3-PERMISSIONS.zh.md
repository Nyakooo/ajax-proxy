# Ajax Proxy 扩展权限与站点范围审查

审查日期：2026-09-25。按 `packages/shell-chrome/manifest.json` 与代码调用点逐项核对。V3 继续以用户主动配置的规则处理任意站点请求，因此内容脚本站点范围仍为广泛授权；本审查验证了 `tabs` 是否冗余，并修正通知 API 使用方式。

| 权限 / 范围                                        | 使用位置                                                              | 功能依据                                                                | 处置                                                                                                                                                                                                   |
| -------------------------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `storage`                                          | `@proxy/shared-utils/storage`、面板配置和 service worker 规则命中计数 | 持久化设置、标签、规则及命中值，并在扩展上下文和标签页间同步            | 保留；扩展主要功能依赖                                                                                                                                                                                 |
| `notifications`                                    | `packages/shell-chrome/src/service-worker/notice.ts`                  | 命中超过阈值时显示系统提醒；点击提醒打开扩展面板                        | 保留；使用 `chrome.notifications`，点击事件在 service worker 顶层注册                                                                                                                                  |
| `tabs`                                             | `chrome.tabs.onActivated` / `chrome.tabs.get`                         | 面板显示当前活动网页标题，并过滤非网页标签                              | 保留；虽然大多数 `tabs` API 方法不要求该权限，但本 manifest 只在 `content_scripts.matches` 声明站点匹配，实测移除后 `chrome.tabs.query()` 返回的 tab 对象不含 `title`。扩展 smoke 会验证活动页标题可读 |
| `content_scripts.matches: ["<all_urls>"]`          | manifest 内容脚本，`all_frames: true`                                 | 代理用户配置的任意站点 Fetch / XHR 请求，并将当前规则状态同步到各 frame | 保留；改为逐站请求会改变扩展安装后的核心工作方式，需要单独设计站点授权 UI                                                                                                                              |
| `web_accessible_resources.matches: ["<all_urls>"]` | manifest 暴露 `document.js`                                           | 内容脚本须在页面主世界挂载请求代理；被匹配页面加载该资源                | 保留，与内容脚本站点范围一致；仅暴露代理脚本资源                                                                                                                                                       |
| `notifications` API                                | `chrome.notifications.create`、`onClicked`、`clear`                   | 构造扩展系统通知并响应点击                                              | 用声明权限对应的扩展 API；不使用 service worker 中的全局 `Notification` 构造器                                                                                                                         |
| `activeTab`、`scripting`                           | 无                                                                    | 当前静态内容脚本不通过用户手势临时注入；没有程序化脚本注入调用点        | 不声明                                                                                                                                                                                                 |

Chrome 文档说明，host permissions 可授予匹配标签页的 URL / 标题访问，且大多数 `tabs` API 功能不需 `tabs` 权限；敏感 tab 属性只有在声明 `tabs` 权限或拥有对应 host permission 时才提供。`content_scripts.matches` 用于脚本匹配，但当前配置并未在 `host_permissions` 声明相同范围，因此实测 `tabs` 权限不能移除。`<all_urls>` 会触发广泛站点访问警告。Chrome 的系统通知由 `chrome.notifications` 提供，并要求 `notifications` 权限。见 [权限声明](https://developer.chrome.com/docs/extensions/develop/concepts/declare-permissions)、[tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs)、[通知 API](https://developer.chrome.com/docs/extensions/reference/api/notifications) 和 [match patterns](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns)。

文件 URL 和隐身窗口仍由用户在浏览器扩展详情页单独授权；`<all_urls>` 不会绕过这些浏览器开关。后续若要提供按站点授权，应将 host pattern 改为可选权限，并在启用代理前请求对应站点访问，不能悄悄缩减现有全站规则的生效范围。
