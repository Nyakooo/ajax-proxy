# V3 配置备份与恢复

本文说明当前 V3 staging 面板中的完整配置备份与恢复流程。V3 面板尚未替换默认 Vue 2 面板；请先构建并加载扩展，再显式打开 `panels-v3/` 页面进行 V3 验收。

## 打开 V3 staging 面板

1. 在仓库根目录运行 `pnpm install --frozen-lockfile` 和 `pnpm build`。
2. 在 Chrome 打开 `chrome://extensions`，启用“开发者模式”，选择“加载已解压的扩展程序”，并选择 `packages/shell-chrome/build`。
3. 在扩展详情页复制扩展 ID，然后打开 `chrome-extension://<扩展 ID>/panels-v3/index.html`。将 `<扩展 ID>` 替换为详情页显示的实际 ID。

V3 页面使用独立的配置存储和消息 adapter。扩展默认打开的仍是 `panels/` Vue 2 页面；在 V3 正式切换前，不能把默认面板中的操作当作 V3 配置操作。

## 导出备份

1. 在 V3 面板点击“备份 / 恢复”。
2. 点击“导出 JSON 备份”，将下载的 `ajax-proxy-v3-backup-YYYY-MM-DD.json` 文件保存在安全位置。

新建配置使用格式版本 7 的完整快照，包含设置、标签、规则和精确 origin 的站点停用列表；版本 3–6 的 V3 备份仍可导入并规范化到版本 7，缺省 / normal / regex matcher 保持原义。版本 4 增加完整 URL 精确匹配，版本 5 增加协议 + 主机名 + 端口级站点开关，版本 6 增加重定向排除子串，版本 7 增加 Fetch-only 函数重定向。命中计数由扩展单独维护，不包含在备份文件中；恢复不会从文件导入计数，若规则 ID 与当前规则相同，扩展可能继续显示该 ID 已有的运行时计数。

每条规则可关联多个标签；备份中的 `rule.tagIds` 必须引用同一文件 `tags` 集合中的标签 ID。恢复会整体保留标签和关联，删除面板标签时会先确认并同步清除规则引用。

规则列表选择一条或多条规则后，可单独导出所选规则。生成的文件只包含所选规则及其引用的标签，并保留当前设置与站点字段；命中计数不导出。当前完整备份使用版本 7 格式；含 `exact` matcher 的历史版本 4、含 `disabledOrigins` 的版本 5、含重定向排除项的版本 6 备份仍可导入。

每条重定向规则可配置最多 100 个排除项。每项是 1–4096 个字符的字面 URL 子串，比较区分大小写，不允许首尾空白或重复项；整个备份的排除文本总计最多 1 MiB。请求 URL 命中排除项时，只有重定向 action 被跳过：若同一规则还启用了响应 action，它仍会处理该响应；否则继续尝试后续规则。导入时会严格校验这些限制；版本 3 / 4 / 5 没有排除项，读入后默认为空。

版本 7 的函数重定向使用 `{ "type": "function", "code": "...", "exclusions": [] }`，不包含静态 `url`。函数体最多 65,536 个字符，执行时只收到原始请求的 URL 和 method，并返回 URL 字符串；相对地址按原始 URL 解析，目标必须是 HTTP(S) 且不能含用户名或密码。备份导入会保留代码并停用 `request.enabled`；同一规则的静态响应 action 保持原设置。V2 备份仍不兼容，V2 `ignores` 不会自动转换；需要时请在 V3 重定向编辑器重新录入排除项。

## 导入并恢复

1. 在 V3 面板打开“备份 / 恢复”，选择 JSON 文件，或将 JSON 粘贴到文本框。
2. 点击“验证备份”并检查校验结果。合法文件会显示规则数量；包含函数代码的备份会另外显示函数 action 数量和不可信代码提示。
3. 确认要用备份中的完整快照替换当前 V3 配置后，点击“确认恢复”。当备份含函数代码时，还需要在浏览器二次确认框中确认。

恢复会整体替换备份所包含的 V3 设置、标签和规则，而不是把规则追加到当前配置。导入的函数 action 会保留代码但保持对应行为停用，不会因恢复而执行；函数重定向停用 `request.enabled`，函数响应停用 `response.enabled`。如需使用，之后要逐条在规则编辑器中明确启用。面板会校验文件格式和 schema；解析或校验失败时显示错误，不保存该文件中的任何配置，当前配置保持不变。

### 追加导入规则

在验证完整 V3 备份后，也可选择“追加规则”。追加操作保留当前设置、已有规则及其顺序，只将文件中当前不存在的规则 ID 加到列表末尾；已有 ID 会在预览中计数并跳过，不覆盖同 ID 规则。URL / method 条件相同但 ID 不同的规则仍会追加，列表顺序决定其优先级，新规则排在现有规则之后。

追加操作只合并新规则实际引用的标签。相同名称的标签会复用当前标签；同一标签 ID 对应不同名称时会阻止追加，避免改写当前标签或关联。整体合并结果仍须通过 V3 schema 校验，否则不会写入。文件中的全局设置和未被新规则引用的标签不会导入。包含函数代码时，浏览器会再次确认；导入的函数 action 保持停用。

## V2 备份不兼容

V3 不支持 V2 配置、规则或备份格式，也不提供自动迁移工具。把 V2 文件导入 V3 会得到格式不兼容提示，不会转换或写入其中的数据。

需要在 V3 使用旧规则时，请先保留原 V2 备份作为参考，然后在 V3 面板中按需重新创建规则并检查匹配条件、动作和优先级。不要把 V2 JSON 直接改字段名后导入；V3 会按版本化 schema 校验完整配置。

## 函数代码与安全

备份中的自定义函数按不可信代码处理。导入预览会提示函数 action 数量；确认恢复后，相关 action 仍保持停用。函数只能在规则编辑器中单独启用，且启用前会展示风险确认。函数响应只作用于 Fetch，XHR 保持原响应；函数重定向也只作用于 Fetch，XHR 保持原 URL 并记录“不支持”结果。

更多执行边界见 [V3 自定义函数能力与安全边界](V3-USER-FUNCTIONS.zh.md)，schema 与校验规则见 [V3 规则模型](V3-RULE-MODEL.zh.md) 和 [V3 输入校验](V3-INPUT-VALIDATION.zh.md)。
