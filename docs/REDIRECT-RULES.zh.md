# 重定向规则使用规范

从 3.0.2 起，V3 静态 URL 重定向恢复正则捕获组替换；Fetch 与 XHR 均支持，无需函数。旧版本将 `$1` 当作普通文本，这是 #59 修复的功能回退。

## 匹配与目标

- 包含 / 精确匹配：目标为固定 URL，不做子串替换，不自动复制原路径或 query。
- 正则匹配、目标无模板：同样直接跳转到固定目标，兼容已有 V3 配置。
- 正则匹配、目标含模板：对原始完整请求 URL 做一次 RE2 替换，再解析目标 URL。未匹配的前后内容保留；建议用 `^` / `$` 锚定完整 URL，避免拼出意外目标。
- 目标允许 HTTP(S) 或相对 URL；相对地址以原始请求 URL 为基准，不以网页地址为基准。

## 保留路径和 query

选择「正则匹配」，匹配 URL：

```text
^https://www\.jingxuesiyingyu\.com/api/(.*)$
```

选择「静态 URL」，目标填写：

```text
https://api.prod.com/$1
```

原请求 `https://www.jingxuesiyingyu.com/api/user/list?page=1` 会发往 `https://api.prod.com/user/list?page=1`。`(.*)` 包含 query；若只捕获路径，则 query 不会自动附加。界面直接填写正则文本，不加 `/.../` 包装；JSON 备份中的反斜杠须按 JSON 规则转义为 `\\`。

支持 RE2 替换模板：`$1`、`$2` 等数字捕获组、`$<name>` 命名捕获组、`$&` 整个匹配、`$$` 字面 `$`、美元符号加反引号表示匹配前文本、`$'` 表示匹配后文本。未参与匹配的可选捕获组替换为空；不存在的组引用按 RE2JS 语义保留为文本。正则模式下需要字面 `$1` 时填写 `$$1`（或 URL 编码 `%241`）。包含 / 精确模式的 `$1` 保持字面值。

## 边界与排错

先确认全局开关、规则与重定向 action 启用、method 匹配、优先级和排除列表，再用匹配试算确认命中。试算用于解释选择规则；以 Network 中实际请求地址验证重定向。选中规则只发送一次请求，不对新目标重新匹配。

正则使用不区分大小写的 RE2，lookahead / lookbehind / 正则 backreference 不支持；目标中的捕获组模板不是正则 backreference。完整 URL 包含协议、主机、端口、路径和 query；匹配的是浏览器规范化后的 URL。

跨源仍受 CORS / preflight 限制，敏感请求头会剔除；替换 URL 不会绕过浏览器权限。静态重定向保留 method、body 和支持的请求参数。目标计算失败时在发请求前回退原 URL；目标已发出后网络失败不重试原地址。

函数重定向仅 Fetch 支持，XHR 保留原 URL；仅换域名 / 路径或使用捕获组时优先使用静态模板。备份无需增加字段或升级格式，原有固定目标规则保持原行为。

可在 [Playground](../pages/playground/index.html) 的用例选择器中选择「正则捕获组重定向」，复制规则并验证 Fetch / XHR。
